# 둘셋 (Dos Tres) · Frontend

둘셋은 청년정책과 지역 활동을 찾고 신청 준비까지 돕는 AI 비서 서비스입니다. 서비스 안의 AI 비서·캐릭터 이름은 조이(JOY)입니다. Figma의 `02 와이어프레임` 12개 화면을 기준으로 만든 React + TypeScript + Vite 프론트엔드입니다.

## 개발 환경

- Node.js 22 LTS, npm
- React 18 · TypeScript · Vite
- 저장소: `dos-tres/frontend`
- 기준 브랜치: `main`

## 처음 실행

```bash
git clone https://github.com/dos-tres/frontend.git
cd frontend
```


```bash
npm install
npm run dev
```

브라우저에서 터미널에 표시된 주소(기본 `http://localhost:5173`)를 엽니다. 종료는 `Ctrl+C`입니다.

캐릭터·배경 PNG 6개는 `assets/images.json`에 원본 바이트를 보관합니다. `npm install`, `npm run dev`, `npm run build`에서 `scripts/restore-assets.mjs`가 `src/assets/`로 자동 복원합니다. 별도 이미지 다운로드는 필요하지 않습니다.

## 빌드 및 미리보기

```bash
npm run build
npm run preview
```

빌드 결과는 `dist/`에 생성됩니다. 미리보기 주소는 터미널에서 확인합니다.

## 마이페이지 및 자가진단

- **내 정보 수정**: 이름·생년월일·전화·이메일·거주 지역 검색과 수정/취소.
- **내 상태 입력**: 활동 상태·경험 추가/수정/삭제·관심 분야·참여 선호.
- **자가진단**: 문항 9개, 이전/건너뛰기, 단일/복수 선택, 결과 확인, 답변 보관 및 수정. 공식 진단이나 위험 등급을 제공하지 않습니다.
- 정보와 점검 결과는 React 메모리에서만 유지하며 새로고침하면 초기화됩니다. 개인정보·활동 정보 저장 API는 아직 없습니다.
- 기존 화면의 공통 색상·카드·버튼을 사용하고, 기본 정보 입력은 PC 2열/모바일 1열로 배치합니다.

### API 연결과 미연결 상태

`GET /api/checkin/questions`와 `POST /api/checkin/summary`를 사용합니다.
문항 조회 실패 또는 2초 시간 초과 시 로컬 문항 스냅샷으로 진행하며, 결과 조회 실패 또는 3초 시간 초과 시 선택 답변 기반 로컬 결과로 전환합니다.
화면에 예시 데이터 배너는 표시하지 않으며 코드 내부에서 결과 출처를 구분합니다. 로컬 결과는 실제 서버 계산 결과가 아닙니다.
다음 진입에서는 API 연결을 다시 시도합니다. 추천·조이 대화 화면은 아직 기존 시연 데이터로 동작하며 점검 응답과 연결하지 않았습니다.

백엔드를 형제 폴더 `../backend`에 두고 의존성을 설치한 뒤 실행합니다.

```bash
# backend 폴더: 의존성이 설치된 가상환경
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# frontend 폴더
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Vite 개발 서버는 `/api`를 `http://127.0.0.1:8000`으로 전달합니다.
별도 API 주소가 필요하면 `VITE_API_BASE_URL`을 지정하고 백엔드 CORS를 맞춥니다.
개발 프록시는 배포에 포함되지 않으므로 배포 시 API 주소 또는 동일 origin의 리버스 프록시가 필요합니다.

### 검증

`npm ci --offline --ignore-scripts`, `npm run build`, 백엔드 상태 점검/추천 API 테스트 11개와 로컬 결과 생성 검증을 통과했습니다.
실제 프론트 API 모듈과 형제 backend의 FastAPI 앱 간 계약은 다음 명령으로 검증합니다.

```bash
BACKEND_PYTHON=../backend/.venv/bin/python node scripts/verify-checkin.mjs
```

ASGI 기반 검증이며 실제 TCP/프록시/브라우저 검증과 다릅니다.
실행 환경의 포트 및 브라우저 연결 제한으로 실제 데스크톱·모바일 화면 검증은 미완료이며 배포하지 않았습니다.
[검증 결과와 백엔드 자료형 검증 수정 예시](docs/verification/checkin-integration.md)를 참고하세요.

## 정책·활동 페이지

백엔드에서 수집한 정책 2,335건과 센터 프로그램 169건으로 목록·상세를 채웁니다. 검색·분류·마감 제외·관심 저장·정렬·페이지 이동과 공식 공고/신청 링크를 제공합니다. 내 정보의 생년월일·거주 지역을 자동 적용하고 기존 추천 API에 보관한 자가진단 답변을 함께 보내 추천 결과/이유를 표시합니다.

서버에 연결되지 않아도 수집된 스냅샷을 검색하고 상세를 볼 수 있습니다. 로컬 탐색은 연령/지역/마감 기준이며 서버의 전체 자격 검증·추천 계산을 대신하지 않습니다. 지역 선택지는 행정표준코드관리시스템 전체 원본의 현존 시·도/시군구 코드로 구성합니다. 정책이 없는 지역도 선택할 수 있으며 정책 데이터에서 지역명을 추측하지 않습니다.

스냅샷은 정책 페이지 진입 시 지연 로딩합니다. 재생성: `BACKEND_PYTHON`에 해당하는 Python으로 `scripts/export-policy-snapshot.py` 실행. 검증: `BACKEND_PYTHON=../backend/.venv/bin/python node scripts/verify-policy.mjs`.

[구현·검증 결과와 필요한 백엔드 API 예시](docs/verification/policy-integration.md)를 참고하세요. 실제 브라우저에서 데스크톱 검색·저장·상세·목록 복귀를 확인했으며 모바일 화면 및 TCP 기반 추천 연동 검증은 남아 있습니다. 배포하지 않았습니다.

### 지역 선택과 기본 조건

정책 지역은 `시·도 → 시·군·구` 두 단계로 선택합니다. 시·도만 고르면 해당 광역 전체를 탐색하고, 시·도를 바꾸면 이전 구 선택은 초기화합니다. 정책 페이지의 나이 입력은 제거했으며 내 정보의 생년월일에서 만 나이를 계산합니다.

처음 진입하거나 내 정보가 바뀌면 저장한 거주 지역·나이·활동 상태를 기본 적용합니다. 다른 지역을 탐색한 뒤 `내 지역으로`를 누르면 내 거주 지역으로 돌아옵니다. 미등록 조건은 임의로 생성하지 않습니다. 정확한 시군구 이름/코드 매핑이 없으면 저장된 시·도 범위로 기본 적용합니다. 시·도 전체 탐색은 로컬 목록을 사용하고, 만 나이와 5자리 시군구가 준비되면 추천 API도 호출합니다.

### 공식 행정구역 사전

지역 선택과 마이페이지 거주지 검색은 [행정표준코드관리시스템](https://www.code.go.kr/stdcode/regCodeL.do)에서 2026-11-20 내려받은 전체 법정동 코드를 사용합니다. 부산 16개 구·군, 대구 9개 구·군(군위군 포함)을 비롯해 현존 시군구/시 전체 코드 269개를 모두 포함합니다. 읍면동은 5,067개이며 정책 유무와 무관하게 선택지를 제공합니다.

원본 ZIP·SHA-256·출처를 보관하고 `python3 scripts/import-administrative-regions.py`로 재생성, `python3 scripts/verify-administrative-regions.py`로 원본의 모든 코드/이름과 대조합니다. 정책 스냅샷도 이 사전을 그대로 사용합니다. 기존 기관명 추측 방식은 제거했습니다. [자료 기준](src/data/regions-source.md).
# 마이페이지와 지역 선택

자가진단은 전체 문항을 한 화면에서 작성하는 설문형입니다. 일상과 마음(5점), 활동과 관계(예/아니오), 필요한 변화와 지원(복수 선택)으로 묶어 표시하며 질문·구역 제목은 18px, 입력 라벨은 16px, 보기·본문·안내는 14px로 통일합니다. 부담·외출 빈도·대화의 충분함·만족도는 점 5개의 척도, 활동·도움을 청할 사람의 유무는 예/아니오, 관심 분야는 복수 선택으로 표시합니다. 모르겠어요·답하지 않을래요·나중에 할게요 선택지는 표시하지 않습니다. 5점 응답 위치는 보관 시 유지하고 기존 서버의 3단계 코드로 변환해 전달합니다. 응답 수를 확인하며 답을 수정하거나 해제할 수 있고, 마지막의 결과 보기로 기존 요약 API에 응답을 전달합니다. 원치 않는 문항은 비워 둘 수 있습니다.

마이 홈에서 기본 정보, 관심 정책·프로그램 수, 등록 활동과 점검 상태를 확인합니다. 좌측 메뉴에서 내 정보, 맞춤 조건·내 상태, 자가진단으로 이동합니다. 기존 공통 색상과 타이포그래피를 사용합니다.

지역은 시·도 → 시·군·구 → 동·읍·면 패널에서 선택 완료 후 반영합니다. 내 정보와 정책 검색에서 같은 공식 지역 사전을 사용하며, 모바일에서는 동·읍·면을 아래에 배치합니다. 동까지 저장해도 추천 API에는 해당 시군구 5자리 코드를 전달합니다. 생년월일·거주 지역·현재 상태·재학 상태와 보관한 관심 분야를 추천 조건에 연결했습니다. 개인 정보와 맞춤 조건은 현재 세션 메모리에 저장되며 새로고침하면 초기화됩니다.

## 상태 점검 결과와 이력

결과 보기에서 답변 목록 대신 유형별 상태와 5개 영역 요약을 표시하고, 응답·5점 위치·결과·시각을 `dos-tres.checkin-history.v1` localStorage에 새 이력으로 저장합니다. 과거 결과 조회, 기존 답변 수정 후 새 이력 저장, 빈 설문으로 다시 시작을 지원합니다. 같은 브라우저·같은 주소에서 새로고침하거나 재방문해도 유지되며 계정/다른 기기 동기화는 없습니다. 브라우저 데이터를 지우면 이력도 삭제됩니다. 저장 실패 시 경고하고 세션 내 결과는 유지합니다. 개인 기본 정보·맞춤 조건은 기존 세션 메모리 저장입니다.

결과 유형별로 고용24·고용복지플러스센터·복지로·1365·보건복지부 공식 지원 안내를 고정 연결합니다. 전국 공통 제도/서비스 안내이며 전 국민에게 조건 없이 지급되는 지원이라는 뜻은 아닙니다. 상태 유형은 응답에 기반한 서비스 내 요약이며 공인 진단/사회조사 유형이 아닙니다.

검증: `node scripts/verify-checkin-history.mjs` (유형·부분 응답·고정 지원 연결·이력 복원·오류 저장소), `npm run build`.

## 백엔드 결과 우선 처리

상태 점검은 항상 `POST /api/checkin/summary`를 먼저 요청합니다. 성공하면 서버의 `levels`, `priority_domains`, `notes`, `disclaimer`, 만족도와 관심 분야를 결과에 반영하고 원본 요약 전체를 이력에 보관합니다. 문항 조회가 실패했더라도 결과 API 호출은 생략하지 않습니다. 연결 실패 시에만 기존 로컬 처리를 사용합니다.

결과 화면에서도 프로필 나이·시군구가 준비되면 `POST /api/recommendations`의 정책·프로그램을 표시합니다. `why`, `income_condition`, `programs_notice`, `notice`, 기관·기간을 표시하고 상세 화면으로 연결합니다. 기본 조건이 없거나 서버 연결이 실패하면 전국 공통 공식 안내를 유지합니다. 정책 목록도 서버의 안내문을 함께 표시합니다.
