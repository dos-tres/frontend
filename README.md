# 둘셋 (Dos Tres) — Frontend

**혼자 시작하기 막막한 청년을 위한 사회참여 AI 비서**

둘셋은 청년정책과 지역 청년센터 프로그램을 **찾는 것부터 신청 준비까지** 연결하는 서비스입니다. 사용자는 긴 검색어를 고민하거나 복잡한 조건을 먼저 알아볼 필요 없이, AI 비서 **조이(JOY)**에게 지금 상황을 이야기하는 것으로 시작할 수 있습니다.

[백엔드 · AI 저장소](https://github.com/dos-tres/backend) · [서비스 핵심 기술](https://github.com/dos-tres/backend#기술-구성과-설계-원칙) · [협업 규칙](docs/GIT_WORKFLOW.md)

---

## 1. 왜 둘셋인가요?

청년에게 필요한 정책과 활동은 많지만, 정보가 여러 기관에 흩어져 있고 자격 조건과 신청 방식도 제각각입니다. 무엇을 찾아야 할지 모르거나 기관에 문의하는 첫 단계부터 부담을 느끼는 청년에게는 **정보의 양보다 다음 행동을 시작할 수 있는 안내**가 중요합니다.

둘셋은 **막연한 고민 → 상황 이해 → 근거 있는 정책·활동 탐색 → 신청 준비 → 일정 관리**라는 흐름을 하나의 웹 서비스로 연결합니다.

## 2. 주요 기능

| 기능 | 사용자 경험 |
| --- | --- |
| **조이와 대화** | “요즘 사람들을 만나고 싶은데 어디서 시작해야 할지 모르겠어”처럼 자연스럽게 말하면, 조이가 필요한 정보를 단계별로 묻고 탐색을 돕습니다. |
| **맞춤 정책·활동 추천** | 거주 지역·연령·현재 상태·관심사와 생활 점검 답변을 바탕으로 정책·프로그램을 보여 주고 추천 이유와 공식 링크를 안내합니다. |
| **정책·프로그램 직접 탐색** | 키워드, 지역, 분야, 모집 여부 등으로 목록을 탐색하고 상세 정보와 신청 경로를 확인합니다. |
| **주변 청년센터 찾기** | 센터 위치·주소·시설·이용 정보·운영 프로그램을 확인하며, 설정된 환경에서는 카카오맵으로 위치를 살펴볼 수 있습니다. |
| **신청서 작성 도우미** | 지원 가능한 Google Form의 질문을 읽고 항목별 답변을 작성·수정합니다. 서술형 답변은 AI 초안을 참고하고 마지막에 전체 내용을 직접 확인합니다. |
| **나의 기록과 일정** | 기본 정보·관심 공고·생활 점검 결과·활동 경험·일정과 신청 관련 기록을 브라우저에 보관하고 다시 확인합니다. |

### 사용자 시나리오

1. **대화 시작** — 조이에게 “취업 준비 중인데 어떤 지원을 받을 수 있어?”라고 말합니다.
2. **조건 확인** — 필요한 경우 거주지·연령·현재 상태 등을 한 가지씩 확인합니다.
3. **공고 탐색** — 실제 수집한 정책·프로그램 중 관련 후보, 추천 이유, 확인이 필요한 자격 조건을 보여 줍니다.
4. **신청 준비** — 공고를 선택해 추가 질문을 하고, 지원되는 신청서의 문항을 확인하거나 문의 대본을 준비합니다.
5. **다음 행동** — 공식 신청 링크를 확인하고 일정·기록을 관리합니다.

> **신청 범위:** 일반 기관의 신청서를 사용자가 검토·작성하는 것은 지원하지만, 기관에 대신 제출하지는 않습니다. 실제 제출은 서버에서 승인한 **팀 소유 복제 테스트 폼**에 한하며, 사용자 최종 확인 뒤 실행됩니다. 전화 문의 역시 대본을 지원하며 자동 발신하지 않습니다.

## 3. AI 비서 조이의 역할

- **이해:** 자유 입력에서 상황·관심사·요청을 정리하고 대화에 필요한 추가 정보를 질문합니다.
- **연결:** 백엔드가 검색·추천한 실제 공고를 바탕으로 결과를 설명하고, 선택한 공고에 대한 후속 질문을 받습니다.
- **준비:** 신청서의 서술형 문항에 대해 사용자가 검토·수정할 수 있는 초안을 만듭니다.
- **구분:** AI가 임의로 정책을 만들어 추천하거나 신청 자격을 최종 보장하지 않습니다. 정책 검색·조건 처리는 백엔드의 카탈로그와 규칙에 기반합니다.

## 4. 서비스 아키텍처

```text
사용자 (PC · 모바일 웹)
        │
        ▼
React + TypeScript + Vite
├─ 홈 · 조이 대화 · 정책/프로그램 · 청년센터 · 신청 도우미
├─ 생활 점검 · 마이페이지 · 일정/기록
├─ browser localStorage (프로필·선택·기록)
└─ Kakao Maps JavaScript SDK (설정 시)
        │  /api/*
        ▼
FastAPI Backend
├─ 대화 이해 및 AI 답변 ─────────── OpenAI API
├─ 정책·프로그램 검색/추천 ──────── PostgreSQL / 서비스 데이터
├─ 지역·센터·생활 점검 API
└─ 신청 문항 확인·답변 초안·승인된 테스트 폼 제출
        ▲
        │
온통청년 정책 API · 청년센터 공고 수집/분류 파이프라인
```

프론트는 **대화와 화면 흐름, 입력·검토, 브라우저 내 기록**을 담당하고, 백엔드는 **공고 데이터·추천 규칙·AI 호출·신청 가능 범위 검증**을 담당합니다. 두 저장소가 같은 API 계약을 사용합니다.

## 5. 프론트엔드 구현

| 항목 | 내용 |
| --- | --- |
| 언어·프레임워크 | TypeScript, React 18, Vite 6 |
| UI | CSS 기반 반응형 레이아웃, `lucide-react`, 조이 캐릭터와 둘셋 브랜드 에셋 |
| API 연동 | Fetch API, 요청 시간 제한·오류 처리, 개발 환경 Vite 프록시 |
| 상태·기록 | 브라우저 `localStorage` 중심의 프로필·관심·생활 점검·일정 관리 |
| 외부 연동 | FastAPI, Kakao Maps JavaScript SDK(선택 설정) |

### 주요 코드

```text
src/
├─ App.tsx                  # 화면 연결과 공통 사용자 흐름
├─ HomeLanding.tsx          # 서비스 홈
├─ chat-api.ts              # 조이 대화 API
├─ assistant-context.ts     # 대화에 전달할 사용자 맥락
├─ PolicyPages.tsx          # 정책·프로그램 탐색 및 상세
├─ policy-api.ts            # 카탈로그·추천 API
├─ CenterPages.tsx          # 청년센터 목록·상세
├─ KakaoCenterMap.tsx       # 카카오맵 연동
├─ ApplyFlow.tsx            # 신청서 작성·검토·테스트 제출
├─ CurrentStateCheck.tsx    # 생활 점검
├─ MyPage.tsx               # 마이페이지
├─ SchedulePages.tsx        # 일정·신청 기록
└─ local-storage.ts         # 브라우저 데이터 저장
```

디자인 에셋은 `public/brand/`, `src/assets/`, 디자인 기준 문서는 `docs/design/`에서 관리합니다.

## 6. 실행 방법

**환경:** Node.js 22 LTS, npm. 백엔드까지 실행하면 실제 정책·센터·대화 API를 연결해서 확인할 수 있습니다.

```bash
git clone https://github.com/dos-tres/frontend.git
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

브라우저에서 **http://127.0.0.1:5173**을 엽니다. 개발 서버는 `/api` 요청을 `http://127.0.0.1:8000`의 백엔드로 전달합니다.

백엔드는 [설치·실행 방법](https://github.com/dos-tres/backend#로컬-실행)을 참고하세요.

### 선택 환경변수

```bash
cp .env.example .env.local
```

`frontend/.env.local`에 필요 시 아래 값을 설정합니다.

| 변수 | 용도 |
| --- | --- |
| `VITE_KAKAO_MAP_APP_KEY` | 카카오맵 JavaScript SDK 키. 카카오 개발자 콘솔에 `http://127.0.0.1:5173` 등의 실제 접속 도메인을 등록해야 합니다. |
| `VITE_API_BASE_URL` | 프론트와 API를 다른 주소에 배포할 때 사용할 공개 API 기본 주소. 로컬 프록시 사용 시 비워 둡니다. |

`VITE_*` 변수는 브라우저에서 볼 수 있습니다. **OpenAI API 키, DB 비밀번호 등 서버 비밀값을 넣지 않습니다.**

### 빌드

```bash
npm run build
npm run preview
```

Vite 결과물은 `dist/`에 생성됩니다. 이미지 자산은 저장소의 `assets/images.json`과 `scripts/restore-assets.mjs`를 통해 설치·개발·빌드 시 복원됩니다.

## 7. 데이터·개인정보 및 검증 기준

- 공고 정보는 공식 출처와 연결하며, **모집 여부·자격·제출 결과는 원문 기준으로 확인**하도록 안내합니다.
- 이름·연락처 등 개인 기본 정보는 추천 요청에 무조건 전송하지 않고, 필요한 조건만 전달하도록 구성합니다. 신청서 초안에서는 개인 식별 정보를 가리는 처리를 사용합니다.
- 사용자 기록은 같은 브라우저에 저장되며, **회원 계정/다른 기기와 동기화되지 않습니다.** 브라우저 데이터 삭제 시 기록도 사라질 수 있습니다.
- 일반 기관 폼의 자동 제출을 지원하지 않습니다. 승인된 팀 소유 복제 폼 제출 여부는 백엔드에서도 다시 검사합니다.
- 구현 검증용 스크립트는 `scripts/verify-*.mjs`, 화면·API 연동 기록은 `docs/verification/`에 있습니다.
