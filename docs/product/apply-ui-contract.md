# 구글폼 신청 UI 연결 현황

2026-11-21. 조이의 선택 공고에서 ‘조이와 신청하기’로 시작한다.

## 이번에 연결한 범위

- `/api/apply/start`에 `item_id`만 전달한다. 이름·생일·연락처·프로필은 전달하지 않는다.
- 문항 전체 표시, 필수 여부·선택지·동의·서술·날짜 입력을 지원한다.
- `fill_key`가 내려오면 기기의 이름·생년월일·연락처·이메일로 일괄 초안을 채운다. 동의는 자동 선택하지 않는다.
- 현재 백엔드에는 `fill_key`가 없어 자동 채움 대신 직접 입력 안내를 표시한다. 문항 제목으로 추정해 개인정보를 채우지 않는다.
- 최종 확인 뒤 사용자 버튼으로만 `/api/apply/submit`에 `item_id`, `answers`를 전송한다. 실제 개인정보는 이 제출 요청에 포함될 수 있다.
- `status=submitted`, `confirmed_by=server`, 일치하는 항목 ID와 유효한 접수 시각을 모두 확인해야 완료로 표시한다.
- 기간을 만들어 표시하지 않고 접수 시각을 한국 시간 신청일로 표시한다. 접수와 선정은 구분한다.
- 조회 마감, 작성 중 마감, 지원 불가, 문항 오류, 접수 여부 불명확을 구분한다. 불명확한 요청은 자동 재전송하지 않는다.
- 완료·마감·확인 불가 카드에서 기존 일정 대화로 연결한다. 일정과 신청 이력을 자동 저장하지 않는다.

## 백엔드와 맞출 사항

`questions`에 이름 `fill_key=name`, 생년월일 `birth_date`, 연락처 `phone`, 이메일 `email`을 붙여 내려주면 로컬 자동 채움이 적용된다. 나이·성별 등 추가 항목은 계약과 프론트 처리를 확정한 뒤 지원한다. 생년월일은 현재 저장 형식 YYYY-MM-DD를 사용하므로 폼별 형식 조건도 필요하다.

`filled`는 현재 조회에 개인정보를 보내지 않아 비어 있어야 한다. 전체 문항 정의를 `questions`로 내려주는 계약을 유지해야 한다.

문항별 길이·형식 등 상세 검증 제약, 기타 직접 입력, 추천 답변 `/draft`, 개인정보 치환·복원, 초안의 자리표시 유지 계약은 후속 연결 범위다. 초안 요청은 아직 보내지 않는다. 현재 기능을 개인정보 치환 구현 완료라고 설명하지 않는다.

서버 확인된 접수 이력의 영속 저장과 재방문 시 중복 제출 방지는 후속 계약이 필요하다. 현재는 진행 중 중복 클릭과 불명확한 결과의 자동 재시도만 방지한다.

테스트 폼 응답·편집 링크는 소스나 문서에 넣지 않는다. 신청 대상 매핑은 기존 백엔드의 로컬 설정을 사용한다. 이번 작업에서는 실제 폼을 호출하거나 제출하지 않았다.

## 검증

프로덕션 빌드 통과. 실제 Chrome의 모의 API로 개인정보 없는 조회, 로컬 자동 채움, 동의 필수 검증, 승인 전 제출 없음, 서버 확인 결과, 일정 연결, 모바일 가로 넘침 없음, 마감 시 제출 버튼 없음 확인. 실제 API 통합·폼 접수 성공은 이 검증에 포함하지 않는다.

## 대화 안에서 공고 선택

별도 검색창·검색 메뉴를 넣지 않는다. 조이 입력창 하나에서 월세·취업 등 관심을 말하면 답변 형태로 최대 세 개의 공고를 제안한다. 처음에만 대화 시작 예시를 표시하고, 공고 선택 뒤에는 조건 확인·신청 준비 등 현재 맥락의 후속 행동을 표시한다.

저장된 나이·지역이 있고 일반 추천을 요청하면 현재 설문과 함께 추천 API를 사용한다. 검색 주제가 있으면 해당 키워드로 공고 API를 조회한다. 이름·연락처·원문 생일은 조회 요청에 포함하지 않는다. 현재 문장 처리는 제한된 키워드 규칙이며 자유 대화 LLM 연결을 완료한 것은 아니다.

공고를 선택해도 기존 대화를 유지한다. 내부 선택 공고에 부모 화면의 다른 관심 저장 콜백을 잘못 적용하지 않는다. 공식 원문은 사용자가 명시적으로 열 때만 별도 창으로 열린다.

모의 Chrome 검증: 입력창 하나 유지, 월세 키워드 요청 반영, 답변 내 공고 선택, 조건·신청 준비 버튼, 화면 이동 없음 확인.
