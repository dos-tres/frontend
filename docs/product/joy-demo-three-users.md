# 조이 해커톤 시연: 사용자 3명 버전

작성일: 2026-11-21 · 시연 시간대: 한국 시간(KST)

관련 문서: [사용자 1명이 세 흐름을 이어가는 버전](joy-demo-single-user.md)

## 시연 방식

지민·수아·민호는 서로 다른 가상 사용자다. 각 시연은 별도의 브라우저 프로필 또는 격리된 테스트 컨텍스트에서 진행한다. 다른 사용자의 로컬 정보·대화·일정·신청 기록을 섞지 않는다. 실제 사용자 브라우저의 데이터를 지우지 않는다.

- 지민: 내 정보·생활점검이 미리 저장된 상태로 시작한다.
- 수아: 내 정보·생활점검·일정이 없는 새 상태로 시작한다.
- 민호: 내 정보만 저장하고 생활점검은 미입력인 상태로 시작한다.

## 목적과 이번 범위

조이는 사용자 상황에 맞는 기회를 찾고, 신청 준비와 참여 일정까지 챙기는 AI 비서다. 짧은 설명과 선택지를 섞고, 이미 저장한 정보는 반복해서 묻지 않는다.

이번 시연은 **① 안내형**을 기준으로 설계한다.

1. 사용자 정보와 생활점검을 프론트 로컬에 저장한다.
2. 추천·AI 요청에 필요한 정보만 전달한다.
3. 정보가 없으면 대화에서 필요한 문항을 하나씩 묻는다.
4. 프로그램 선택 → 신청 답변 초안 → 사용자 내용 확인 → 신청 화면 연결로 진행한다.
5. 사용자가 신청했다고 확인하면 사용자 확인 기록을 남기고, 참여 날짜·시간을 확인해 일정 등록을 제안한다.

이 문서는 시연 기획이며, 아래 대화가 모두 현재 구현됐다는 뜻은 아니다. 실제 LLM 연결과 신청 연동은 별도로 구현·검증해야 한다. 회원가입·로그인과 실제 전화 대행은 이번 기본 흐름에 포함하지 않는다.

## 실제 정보와 시연용 설정 구분

- 페르소나의 이름·나이·거주 동네는 가상이다.
- 센터는 실제 기관이며, 아래 주소는 프로젝트에서 확인한 공식 센터 안내를 기준으로 한다. 시연 전 최신 안내를 다시 확인한다.
- **프로그램 이름·모집 조건·날짜·시간은 가상이다.** 실제 모집·예약·접수 결과처럼 표시하지 않는다.
- 가상 프로그램 카드는 `[시연용]`으로 표시한다. 실제 공고를 확정하면 이름·신청 조건·신청 기간·참여 장소·참여 일정을 함께 교체한다.
- 거주 동네는 시나리오를 구체화하기 위한 설정이다. 현재 추천 API에는 지원하는 시군구 코드 단위로 전달하고, 정확한 집 주소는 요구하지 않는다.
- 신청 마감일과 실제 참여일은 구분한다. 센터 주소와 프로그램 행사 장소가 같은지도 확인한다.
- 실제 기관에 신청하거나 문의하지 않는다. 반복 제출 시연은 사용자가 만든 테스트 신청서만 사용한다.
- 개인 전화번호·테스트 폼 URL·API 키·인증정보는 이 문서와 코드·커밋에 넣지 않는다.

## 1. 지민: 봉천동 거주 → 신림동 센터에서 취업 준비

### 설정

- 거주지: 서울 관악구 봉천동
- 센터: 서울청년센터 관악
- 시연 장소: 서울 관악구 신림로 99, 청년활력공간 1~2층
- 시연용 프로그램: 함께 준비하는 취업 스터디
- 시연 일정: 2026-11-27(금) 19:00~21:00
- 저장 정보: 나이·거주 지역·구직 상태·관련 관심 분야와 생활점검 답변

### 대화와 화면

**사용자:** “봉천동 사는데, 취업 준비하면서 사람도 만날 수 있는 거 있을까?”

**조이:** “취업 준비와 교류를 함께할 수 있는 활동을 찾아볼게요. 저장한 관악구·구직 중 정보를 사용할게요.”

화면: 실제 API 결과를 보여주는 프로그램 카드. 가상 데이터로 시연할 때는 `[시연용]` 표시.

**사용자:** “함께 준비하는 취업 스터디 알아봐 줘.”

**조이:** “함께 취업 준비를 하면서 소규모로 교류하는 프로그램이에요. 참여 조건과 준비할 내용을 정리했어요.”

화면: 대상·신청 기간·참여 장소·참여 일정 카드와 `[신청 준비하기]`, `[다른 활동 보기]`.

**사용자:** “신청 준비해 줘.”

**조이:** “저장한 정보로 채울 수 있는 항목은 정리했어요. 참여하고 싶은 이유만 알려주세요.”

선택지: `[취업 준비 습관 만들기]` `[같이 준비할 사람 만나기]` `[직접 입력]`

**사용자:** “같이 준비할 사람 만나기.”

**조이:** “이렇게 작성하면 어떨까요?”

화면: 수정 가능한 참여 동기 초안. 사용자 확인 후 `[답변 복사하고 신청 화면 열기]`.

신청 화면에서 돌아오면 조이가 “신청을 마쳤나요?”라고 묻는다.

선택지: `[신청했어요]` `[아직이에요]`

`신청했어요` 선택 시 기관의 접수 확인이 아닌 **사용자가 신청했다고 확인한 기록**으로 남긴다.

**조이:** “11월 27일 금요일 오후 7시부터 9시, 서울청년센터 관악 일정으로 등록할까요?”

화면: 달력·제목·시간·장소 미리보기와 `[확인하고 등록]` `[내용 수정]` `[취소]`.

### 확인 기준

- 이미 저장한 나이·거주지·상태를 다시 묻지 않는다.
- 신청서가 요구하는 항목만 준비하고, 참여 동기 초안은 수정할 수 있다.
- 신청 화면 열기만으로 신청 완료 처리하지 않는다.
- 일정은 사용자 확인 후 저장하고 내 일정에서 확인할 수 있다.

## 2. 수아: 천호동 거주 → 성내동 센터에서 첫 모임

### 설정

- 거주지: 서울 강동구 천호동
- 센터: 서울청년센터 강동
- 시연 장소: 서울 강동구 올림픽로 610, 천호역 효성해링턴타워 B동 2층
- 시연용 프로그램: 처음 만나는 동네 모임
- 시연 일정: 2026-11-28(토) 11:00~12:00
- 저장 정보: 없음

### 대화와 화면

**사용자:** “천호동 근처에서 가볍게 참여할 만한 거 있어?”

**조이:** “처음에는 어떤 활동이 편해요?”

선택지: `[작은 모임]` `[함께 배우는 활동]` `[온라인부터]`

**사용자:** “작은 모임.”

**조이:** “서울 강동구 천호동을 말씀하신 걸까요?”

선택지: `[네, 강동구예요]` `[다른 지역이에요]`

**사용자:** “네, 강동구예요.”

**조이:** “신청 대상 나이도 확인할게요. 생년월일을 알려주세요. 건너뛰어도 괜찮아요.”

화면: 생년월일 입력과 작은 건너뛰기 동작. 한 번에 전체 설정 폼으로 보내지 않는다.

**조이:** “현재 재학 중인가요?”

선택지: `[대학생]` `[대학원생]` `[학생이 아니에요]` 등 지원하는 실제 항목.

**사용자:** “대학생.”

대화에서 확인한 정보는 로컬에 저장하고, 추천 요청에 필요한 형식으로 전달한다. 건너뛴 나이 등은 미확인 상태를 유지한다.

**조이:** “강동구에서 참여할 수 있는 작은 모임을 찾아봤어요.”

화면: 실제 추천 응답의 결과 카드. 실제로 조회되지 않았으면 조회했다고 말하지 않는다.

프로그램 선택 후 신청 준비·신청 화면 연결·사용자 신청 확인을 거쳐, **11월 28일 11:00~12:00** 일정 확인 카드로 연결한다.

### 확인 기준

- 이미 말한 천호동을 활용하고, 불명확한 행정구역은 확인한다.
- 필요한 문항을 하나씩 묻고 답한 값만 저장한다.
- 건너뛴 정보를 추정하거나 전체 설문 작성을 강제하지 않는다.
- 입력 정보가 부족하면 부족한 조건을 설명하며 신청 가능 여부를 단정하지 않는다.

## 3. 민호: 합정동 거주 → 중구 활동의 타 지역 참여 조건 확인

### 설정

- 거주지: 서울 마포구 합정동
- 센터: 서울청년센터 중구
- 시연 장소: 서울 중구 서소문로12길 36, 8층
- 시연용 프로그램: 주말 커리어 워크숍
- 시연 일정: 2026-11-28(토) 14:00~16:00
- 저장 정보: 나이·거주 지역·재직 상태. 생활점검 미입력
- 가상 공고 조건: 마포구 거주 재직자의 참여 가능 여부가 공고에 명확하지 않음

### 대화와 화면

**사용자:** “이 중구 프로그램, 마포구 사는 직장인도 신청할 수 있어?”

**조이:** “공고에는 거주지 제한이 명확하게 적혀 있지 않아요. 지금 정보만으로 신청 가능하다고 확정하기는 어려워요.”

선택지: `[문의 대본 받기]` `[조건이 명확한 다른 활동 보기]`

**사용자:** “문의 대본 정리해 줘.”

조이는 다음 문의 대본을 카드로 보여준다.

> 프로그램 참여를 알아보고 있어요. 마포구에 거주하는 재직자도 신청할 수 있는지, 별도로 준비할 서류가 있는지 확인하고 싶어요.

선택지: `[대본 복사]` `[공식 안내 열기]`

**사용자:** “대신 전화해 줄 수 있어?”

**조이:** “전화 대행은 아직 지원하지 않아요. 직접 문의할 때 사용할 대본은 수정해 드릴 수 있어요.”

시연에서는 실제로 전화하거나 문의하지 않고, 아래 사용자 확인 발화도 시나리오로 진행한다.

**사용자:** “참여 가능하다고 안내받았어. 11월 28일 토요일 오후 2시부터 4시래.”

**조이:** “참여 가능한 것으로 안내받았군요. 신청 준비를 이어갈까요?”

이는 **사용자가 전달한 확인 내용**으로 구분한다. 조이가 기관에 직접 확인했다고 말하지 않는다.

신청 준비와 사용자 신청 확인 후 **11월 28일 14:00~16:00, 서울청년센터 중구** 달력 카드로 일정 등록을 제안한다.

### 확인 기준

- 사용자의 거주 구와 활동 장소의 구를 구분한다.
- 생활점검 전체를 마쳐야 공고를 볼 수 있도록 막지 않는다.
- 자격이 불명확하면 문의 준비나 다른 활동 탐색을 제안한다.
- 전화 대행·실제 기관 확인·접수 성공을 수행한 것처럼 표시하지 않는다.

## 공통 UI와 조이 말투

| 단계 | 보여줄 UI | 사용자 결정 |
|---|---|---|
| 필요한 정보 확인 | 짧은 말풍선 + 문항 하나 + 선택지 | 답변·건너뛰기 |
| 프로그램 탐색 | API 결과 카드, 분야·지역·신청 기간 | 프로그램 선택 |
| 신청 준비 | 필요한 추가 질문, 수정 가능한 답변 초안 | 초안 확인·수정 |
| 안내형 신청 연결 | 답변 복사, 공식 신청 화면 링크 | 직접 신청 진행 |
| 신청 결과 기록 | 신청 여부 확인 선택지 | 신청했다고 확인하거나 보류 |
| 일정 등록 | 날짜가 강조된 달력, 시간·장소 미리보기 | 확인하고 등록·수정·취소 |
| 조건 불확실 | 공고 근거, 문의 대본, 다른 활동 선택지 | 직접 확인하거나 대안 선택 |

- 해요체로 짧게 말하고 질문은 한 번에 하나씩 한다.
- 자유 입력과 선택지를 함께 제공하되, 신청·기록·일정 저장은 명확한 확인 동작을 둔다.
- 확인된 사실, 사용자 발언, 조이가 만든 초안을 구분한다.
- 결과가 없거나 API가 실패하면 그 상태를 설명한다. 시연용 결과로 몰래 대체하지 않는다.

## ② 실행형으로 확장할 지점

초안 작성·내용 확인·결과 기록·달력 확인 UI는 재사용한다. 실행형이 준비되면 안내형의 신청 화면 연결 지점에 다음을 추가한다.

1. 지원하는 신청 대상인지 확인한다.
2. 부족한 정보만 받고, 제출할 항목을 사용자에게 보여준다.
3. 로그인·본인인증은 필요할 때 사용자가 직접 수행한다.
4. 확정한 대상·입력·첨부 내용에 대한 최종 승인을 받는다.
5. 승인한 내용만 제출하고 실제 접수 결과를 확인한다.
6. 성공이 확인된 경우에만 접수 기록을 남긴다. 결과가 불명확하면 자동 재제출하지 않는다.

자동 제출이 지원되지 않으면 준비한 답변과 공식 신청 링크를 제공해 안내형으로 이어간다. 테스트 폼 시연과 실제 기관 연동은 명확하게 구분한다.

## 시연 전에 확정할 항목

- 세 시나리오에 연결할 실제 공고 또는 명시적인 시연용 데이터
- 공고별 신청 대상·신청 기간·행사 장소·참여 날짜와 시간
- 신청서에서 요구하는 추가 문항과 답변 초안
- 안내형 신청 결과의 사용자 확인 문구
- 사용자가 만든 테스트 신청서와 실행형 백엔드의 지원 여부
- 원문·기관 안내의 최신성 및 데이터 출처

현재 문서에는 실제 신청 폼 링크나 연락처를 넣지 않는다. 문서 작성은 코드 구현·LLM 연결·기관 신청을 수행한 것으로 간주하지 않는다.
