# 조이 해커톤 시연: 사용자 1명이 세 흐름을 이어가는 버전

작성일: 2026-11-21 · 시연 시간대: 한국 시간(KST)

관련 문서: [사용자 3명이 각각 시작하는 버전](joy-demo-three-users.md)

## 목적과 시연 방식

한 명의 사용자가 같은 브라우저에서 조이를 사용하며 다음 세 가지를 순서대로 경험한다.

1. 정보가 없는 상태에서 대화로 필요한 정보를 입력하고 첫 활동을 찾는다.
2. 저장된 정보를 재사용해 다른 활동의 신청을 준비한다.
3. 다른 구의 활동에서 애매한 자격을 확인하고 문의 대본·일정 기록으로 이어간다.

단계 사이에 사용자를 바꾸거나 로컬 데이터를 초기화하지 않는다. 앞에서 입력한 정보와 등록한 일정이 다음 단계에 유지되는 모습을 보여준다.

이번 기본 설계는 **① 안내형**이다. 프로그램 선택 → 신청 답변 초안 → 사용자 확인 → 공식 신청 화면 연결 → 사용자 신청 여부 확인 → 일정 등록으로 진행한다. 이 문서는 기획이며 모든 대화와 AI 기능이 구현됐다는 뜻은 아니다.

## 실제 정보와 가상 설정 구분

- 이름·나이·거주 동네와 프로그램 이름·조건·날짜·시간은 가상이다.
- 센터는 실제 기관이며 주소는 프로젝트에서 확인한 공식 안내 기준이다. 시연 전에 최신 안내를 다시 확인한다.
- 모든 가상 프로그램 카드에 `[시연용]` 표시를 붙인다. 실제 모집·예약·접수 성공처럼 표시하지 않는다.
- 실제 공고로 교체할 때는 신청 대상·신청 기간·행사 장소·참여 일정도 함께 교체한다. 센터 주소가 실제 행사 장소인지 확인한다.
- 실제 기관에 신청하거나 문의하지 않는다. 반복 제출 시연은 사용자가 만든 테스트 신청서만 사용한다.
- 개인 전화번호·테스트 폼 URL·API 키·비밀번호·인증번호는 문서·코드·커밋에 넣지 않는다.

## 공통 사용자

| 항목 | 설정 |
|---|---|
| 이름 | 지민, 가상 사용자 |
| 나이·상태 | 25세, 구직 중 |
| 거주지 | 서울 관악구 봉천동 |
| 관심 | 취업 준비와 부담 적은 교류 |
| 시작 상태 | 내 정보·생활점검·신청 이력·일정 미입력 |
| 사용 환경 | 실제 사용자와 분리한 시연용 브라우저 |
| 목표 | 취업 준비를 이어가면서 사람들과 만날 기회 만들기 |

거주 동네는 시나리오를 구체화하기 위한 설정이다. 현재 추천 API에는 지원하는 시군구 코드 단위로 전달하고 정확한 집 주소는 요구하지 않는다. 구직 상태는 세 단계 내내 유지한다.

## 세 가지 활동과 일정

| 순서 | 보여줄 흐름 | 시연용 프로그램 | 실제 센터 | 가상 참여 일정 |
|---|---|---|---|---|
| 1 | 필요한 정보 하나씩 입력 | 함께 준비하는 취업 스터디 | 서울청년센터 관악 | 2026-11-27(금) 19:00~21:00 |
| 2 | 저장 정보 재사용·신청 초안 | 처음 만나는 동네 모임 | 서울청년센터 강동 | 2026-11-28(토) 11:00~12:00 |
| 3 | 타 지역 참여 조건 확인 | 주말 커리어 워크숍 | 서울청년센터 중구 | 2026-11-28(토) 14:00~16:00 |

가상 일정은 서로 겹치지 않도록 정했다. 실제 행사로 교체하면 이동 여유와 이용 가능 시간도 다시 확인한다.

## 1. 정보 없이 시작 → 관악구 활동 찾기

### 장소와 시작 상태

- 거주지: 서울 관악구 봉천동
- 활동 장소: 서울청년센터 관악, 서울 관악구 신림로 99, 청년활력공간 1~2층
- 가상 일정: 2026-11-27(금) 19:00~21:00
- 내 정보와 생활점검은 아직 없다. 조이가 저장 정보를 이미 알고 있다고 말하면 안 된다.

### 대화와 UI

**사용자:** “취업 준비하면서 사람도 좀 만나고 싶은데, 어디부터 알아봐야 할지 모르겠어.”

**조이:** “처음에는 어떤 활동이 편해요?”

선택지: `[작은 모임]` `[함께 배우는 활동]` `[온라인부터]`

**사용자:** “작은 모임.”

**조이:** “가까운 활동을 찾으려면 거주 지역이 필요해요. 어느 동네에 살고 있나요?”

**사용자:** “서울 관악구 봉천동.”

**조이:** “신청 대상 나이도 확인할게요. 생년월일을 알려주세요. 건너뛰어도 괜찮아요.”

사용자가 실제 있는 날짜로 25세에 해당하는 가상 생년월일을 입력한다. 전체 설정 화면으로 이동시키지 않는다.

**조이:** “지금 어떤 상태인가요?”

선택지: `[구직 중]` `[재직 중]` `[재학 중]` 등 실제 지원 항목.

**사용자:** “구직 중.”

**조이:** “관심 있는 지원도 골라주세요. 최대 3개까지 선택할 수 있어요.”

**사용자:** `[취업·진로]` `[지역 활동]`

답한 정보만 브라우저 로컬에 저장하고 추천 요청에 전달한다. 생활점검 전체 완료를 강제하거나 입력하지 않은 답을 추정하지 않는다.

**조이:** “관악구에서 함께 취업을 준비할 수 있는 활동을 찾아볼게요.”

화면: API에서 실제로 받은 결과 카드. 가상 프로그램을 표시한다면 `[시연용] 함께 준비하는 취업 스터디`로 명시한다.

사용자가 프로그램을 고르면 대상·신청 기간·장소·일정을 보여주고 신청 준비를 진행한다. 신청 화면을 열었다는 이유만으로 완료 처리하지 않는다.

신청 안내를 마치고 사용자가 `[신청했어요]`라고 확인하면 다음을 제안한다.

**조이:** “11월 27일 금요일 오후 7시부터 9시, 서울청년센터 관악 일정으로 등록할까요?”

화면: 달력·제목·시간·장소 카드와 `[확인하고 등록]` `[내용 수정]` `[취소]`.

### 단계 종료 상태

- 내 정보: 거주 지역·생년월일·구직 상태 등 실제 답한 정보만 저장됨.
- 관심 분야: 취업·진로, 지역 활동 저장됨.
- 생활점검: 실제 답한 문항만 존재하며 전체 완료로 처리하지 않음.
- 신청 이력: 사용자 확인 기준임을 표시한 첫 기록.
- 일정: 사용자가 확인했다면 11월 27일 취업 스터디 1건.

## 2. 저장 정보 활용 → 강동구 활동 신청 준비

### 장소와 시작 상태

- 거주지는 계속 서울 관악구 봉천동이다. 강동구로 바꾸지 않는다.
- 활동 장소: 서울청년센터 강동, 서울 강동구 올림픽로 610, 천호역 효성해링턴타워 B동 2층
- 가상 일정: 2026-11-28(토) 11:00~12:00
- 1단계에서 입력한 정보와 일정이 그대로 남아 있다.

### 대화와 UI

**사용자:** “토요일에는 다른 동네 모임도 가보고 싶어. 강동구 쪽에도 있을까?”

**조이:** “거주지는 관악구로 유지하고, 활동 지역을 강동구로 찾아볼게요.”

조회 지역과 거주 지역을 구분한다. 강동구 활동을 검색했다고 로컬 거주지나 추천 자격 정보를 덮어쓰지 않는다.

화면: 강동구 프로그램 카드. 실제 결과가 없으면 없다고 안내한다. 가상 프로그램은 `[시연용] 처음 만나는 동네 모임`으로 표시한다.

**사용자:** “이 모임 신청 준비해 줘.”

**조이:** “저장한 정보로 준비할 수 있는 항목은 정리했어요. 참여하고 싶은 이유만 알려주세요.”

선택지: `[새로운 사람 만나기]` `[다른 동네 경험하기]` `[직접 입력]`

**사용자:** “새로운 사람 만나기.”

**조이:** “이렇게 작성하면 어떨까요?”

화면: 수정 가능한 참여 동기 초안. 예: “취업 준비 중 새로운 사람들과 편하게 교류하고 싶어 참여를 희망합니다.”

사용자 확인 후 `[답변 복사하고 신청 화면 열기]`로 이어간다. 실제 신청서에서 요구하지 않는 정보는 추가로 받지 않는다.

사용자가 신청했다고 확인하면 사용자 확인 기록을 남긴다.

**조이:** “11월 28일 토요일 오전 11시부터 낮 12시, 서울청년센터 강동 일정으로 등록할까요?”

화면: 달력 확인 카드. 저장하면 내 일정에 기존 관악구 활동과 강동구 활동이 함께 표시된다.

### 단계 종료 상태

- 거주지: 관악구 그대로 유지.
- 나이·구직 상태: 다시 묻지 않음.
- 신청 이력: 사용자 확인 기준의 기록 2건.
- 일정: 사용자 확인 후 2건. 서로 다른 날짜·장소가 구분됨.

## 3. 자격이 애매한 경우 → 중구 활동 문의 준비

### 장소와 시작 상태

- 거주지: 계속 서울 관악구 봉천동
- 활동 장소: 서울청년센터 중구, 서울 중구 서소문로12길 36, 8층
- 가상 일정: 2026-11-28(토) 14:00~16:00
- 가상 공고에는 다른 구 거주 구직자의 참여 가능 여부가 명확하지 않다.
- 기존 정보·신청 이력·일정 2건은 유지한다.

### 대화와 UI

**사용자:** “이 중구 워크숍, 관악구 사는 사람도 신청할 수 있어?”

**조이:** “공고에는 거주지 제한이 명확하게 적혀 있지 않아요. 지금 정보만으로 신청 가능하다고 확정하기는 어려워요.”

선택지: `[문의 대본 받기]` `[조건이 명확한 다른 활동 보기]`

**사용자:** “문의할 내용 정리해 줘.”

문의 대본 카드:

> 프로그램 참여를 알아보고 있어요. 관악구에 거주하는 구직자도 신청할 수 있는지, 별도로 준비할 서류가 있는지 확인하고 싶어요.

선택지: `[대본 복사]` `[공식 안내 열기]`

**사용자:** “대신 전화해 줄 수 있어?”

**조이:** “전화 대행은 아직 지원하지 않아요. 직접 문의할 때 사용할 대본은 수정해 드릴 수 있어요.”

시연에서는 실제 문의하지 않는다. 다음 발화는 가상 시나리오의 사용자 확인 발화다.

**사용자:** “관악구 살아도 참여 가능하다고 안내받았어.”

**조이:** “참여 가능한 것으로 안내받았군요. 신청 준비를 이어갈까요?”

사용자 발언으로 전달받은 내용과 기관에서 직접 받은 확인을 구분한다. 조이가 직접 전화했다고 말하지 않는다.

신청 준비·사용자 신청 확인을 거쳐 다음 일정을 제안한다.

**조이:** “11월 28일 토요일 오후 2시부터 4시, 서울청년센터 중구 일정으로 등록할까요?”

화면: 달력·제목·시간·장소 확인 카드. 같은 날 오전의 강동구 일정도 유지한다. 실제 이동 가능 시간을 확인하지 않았다면 여유 있게 이동할 수 있다고 단정하지 않는다.

### 단계 종료 상태

- 사용자와 거주 정보는 처음부터 끝까지 동일하다.
- 사용자 확인 기준의 신청 기록과 등록한 일정이 각각 3건으로 이어진다.
- 마지막 내 일정 리스트에서 관악·강동·중구의 날짜·시간·장소를 함께 확인한다.
- 확인하지 않거나 취소한 항목은 저장 건수에 포함하지 않는다.

## 공통 UI·데이터 원칙

| 항목 | 기준 |
|---|---|
| 입력 | 필요한 문항 하나씩, 선택지와 직접 입력 병행 |
| 저장 | 답한 값만 로컬 저장, 기존 기록 보존 |
| AI 전달 | 추천·대화에 필요한 정보만 전달 |
| 지역 | 거주 지역과 활동 검색 지역·행사 장소를 분리 |
| 신청 초안 | 실제 요구 항목만 준비하고 사용자가 수정 가능 |
| 안내형 완료 | 사용자가 신청했다고 확인한 기록으로 표시 |
| 일정 저장 | 달력 미리보기와 명시적 확인 후 저장 |
| 실패 | 결과 없음·API 실패·조건 미확인을 실제 상태대로 안내 |
| 전화 | 문의 대본만 제공, 전화 대행을 수행했다고 말하지 않음 |

## ② 실행형으로 확장

프로그램 선택·추가 질문·초안·확인·결과 기록 UI는 공통으로 사용한다. 지원하는 신청 대상에 한해 최종 내용 승인 → 실제 입력·제출 → 접수 결과 확인을 연결한다.

- 로그인·본인인증은 필요한 시점에 사용자가 직접 수행한다.
- 비밀번호·인증번호를 LLM에 전달하지 않는다.
- 제출 대상·내용·첨부가 바뀌면 다시 확인한다.
- 결과가 불명확하면 자동 재제출하지 않는다.
- 자동 제출을 지원하지 않으면 준비한 답변과 공식 신청 링크로 안내형을 이어간다.
- 테스트 신청서 제출과 실제 기관 연동을 명확히 구분한다.

## 시연 확인 순서

1. 분리된 시연 브라우저에서 내 정보·신청 이력·일정이 비어 있는지 확인한다.
2. 첫 대화에서 필요한 정보만 입력하고 로컬 저장과 추천 요청의 반영을 확인한다.
3. 첫 신청 확인과 일정 등록 후 기록이 1건인지 확인한다.
4. 강동구 검색이 거주지를 바꾸지 않는지, 저장 정보를 다시 묻지 않는지 확인한다.
5. 두 번째 일정 등록 후 기존 기록이 유지되는지 확인한다.
6. 중구 참여 조건이 미확인일 때 단정하거나 문의를 수행한 것처럼 말하지 않는지 확인한다.
7. 세 번째 일정 확인 후 캘린더·리스트의 날짜·시간·장소와 저장 건수를 대조한다.
8. 새로고침 후 로컬 정보와 등록한 일정이 유지되는지 확인한다. 대화 자체의 저장 여부와는 구분한다.

## 시연 전 확정할 항목

- 실제 API 공고 또는 명시적인 가상 시연용 데이터
- 공고별 자격·신청 기간·참여 날짜·장소
- 신청서 추가 문항과 답변 초안
- 사용자 확인 기록 문구와 달력 카드
- 사용자 소유 테스트 신청서 및 실행형 지원 여부

이 문서 작성은 실제 LLM 연결·신청·문의·예약을 수행한 것으로 간주하지 않는다.
