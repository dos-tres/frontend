# 필수 시연영상 1 — 강동구 수아: 대화 → 테스트 구글폼 신청 → 문의 대본 → 일정 등록

작성일: 2026-11-21 · 기준 시간대: 한국 시간(KST)

선택 영상: [페르소나 2 — 관악구 지민의 정책 신청 안내](joy-demo-persona-02-policy.md)

우선순위: **이 영상부터 완성·촬영한다.** 구글폼 테스트 완료는 사용자 공유 상태다. 이번 문서 수정에서 재제출하거나 성공을 새로 검증한 것은 아니다. 기존 테스트 성공 경로를 재사용하고, 새로운 외부 사이트 자동화는 필수 범위에 넣지 않는다.

## 1. 영상에서 보여줄 메시지

**대화로 필요한 정보를 채우고 프로그램을 찾는다. 지원하는 테스트 구글폼은 확인 후 실제 제출하고, 전화 대신 문의 대본과 문의할 일정을 남긴다.**

이 영상은 ‘구글폼 실제 제출’을 보여줄 핵심 영상이다. 이미 테스트한 팀 소유 폼을 기준으로 촬영한다. 전체 대화 UI 연결까지 완료됐다는 의미는 아니므로, 현재 연결된 화면을 기준으로 아래 대본을 맞춘다. 신청 화면을 열거나 초안을 만든 것만으로 제출됐다고 말하지 않는다.

## 3. 대화로 채울 답변

두 번째 영상과 다른 상황을 명확하게 보여준다. 이미 대화로 답한 문항을 전체 설문에서 다시 묻지 않는다.

| 항목 | 사용자 답변의 의미 | 요청 값 |
|---|---|---|
| 현재 상태 | 대학생 | job=학생, school=대학생 |
| 생활 부담 | 크지 않은 편 | economy=low |
| 정기 활동 | 학교 수업에 정기적으로 참여 | participation=low |
| 외출 | 필요한 일 외에는 거의 안 나감 | outing=high |
| 대화·교류 | 부족하다고 느낌 | conversation=high |
| 도움받을 관계 | 잘 모르겠음 | support=mid |
| 생활 만족 | 보통 | satisfaction=normal |
| 대면 활동 | 많이 부담 | face_to_face=high |
| 관심 | 교류, 문화·여가 | interests=['사람 만나기·모임','문화·여가'] |

모든 항목을 첫 대화에서 한꺼번에 묻지 않는다. 추천에 필요한 순서로 하나씩 확인하고, 나머지는 로컬 시연 데이터로 미리 준비할 수 있다. 미리 준비한 값은 ‘대화로 방금 입력했다’고 말하지 않는다.

## 4. 실제 후보와 테스트 신청 대상 분리

2026-11-21 위 프로필·답변으로 로컬 추천을 조회했으며 `source=db`를 확인했다.

- 실제 상위 정책 예: 국립 문화시설 청년할인, 2026 서울청년문화패스 지원, 2026 7979 서울 러닝크루.
- 추천 상위 프로그램은 금천 북캉스·관악 청년연합체육대회·강북 유스터마이징으로 확인됐다. 현재 추천 API의 상위 결과가 거주 구 내부 프로그램만을 보장하지는 않는다.
- 영상에서는 주변센터의 강동 센터로 이동해 지역 프로그램을 별도로 선택한다. 추천 1위라고 표현하지 않는다.
- 강동 센터에서 선택할 실제 프로그램 후보: **서울청년센터 강동 <2026년 크리스마스 연말 파티 & 성장공유회> 참여자 모집**.
- 로컬 항목 ID: `program:orang:75815`.
- 로컬 데이터의 신청 기간: 2026-11-11~2026-12-02.
- 로컬 장소: 서울청년센터 강동 공용공간 및 강의실.
- 로컬 신청 대상은 ‘기타’이며 신청 방법은 비어 있었다. **이 정보만으로 수아의 참여 가능 여부나 구글폼 신청 가능 여부를 확정하지 않는다.**

위 공고를 추천·내용 확인의 실제 데이터 예로 사용할 수 있다. 실제 기관 신청서는 제출하지 않는다.

제출 장면은 별도의 **`[둘셋 시연용] 강동 청년 교류 모임 테스트 신청`**으로 진행한다. 실제 공고에서 팀 소유 테스트 신청서로 넘어가는 지점에 ‘테스트 신청서’ 표시를 유지한다. 실제 행사의 구글폼 제출인 것처럼 연결하지 않는다.

테스트 폼에서 사용할 가상 행사 설정:

| 필드 | 테스트 설정 |
|---|---|
| 프로그램 | [둘셋 시연용] 강동 청년 교류 모임 |
| 참여일 | 2026-12-05(토) |
| 참여 시간 | 14:00~16:00 |
| 장소 표시 | [시연용] 서울청년센터 강동 공간을 가정 |
| 성격 | 팀 소유 폼을 통한 제출 기능 검증. 실제 행사·예약 아님 |

이 날짜·시간은 실제 연말 파티 공고의 행사일이 아니다. 실제 공고의 행사일을 확인하지 못했다면 원래 공고 카드에 이 가상 일정을 붙이지 않는다.

## 5. 촬영 전 연결 체크리스트

- 팀이 직접 만든 테스트 폼이 응답 가능 상태인지 확인한다.
- 테스트 폼을 백엔드의 로컬 신청 대상 설정에 등록한다. 폼 주소·편집 주소는 문서·코드·커밋에 넣지 않는다.
- 선택할 item_id와 테스트 폼의 연결을 확인한다. 실제 기관 폼으로 연결돼 있으면 중단한다.
- `/api/apply/start`가 실제 문항·미리 채운 값·남은 질문·동의 항목을 반환하는지 확인한다.
- 긴 답변 초안은 사용자가 말한 사실만 사용하고 수정할 수 있게 한다.
- 동의 항목은 사용자가 직접 선택한다. 미리 선택하지 않는다.
- 최종 확인 화면 뒤에서만 `/api/apply/submit`을 한 번 호출한다.
- 실제 제출 성공 응답과 팀 소유 폼의 응답 건수 증가를 대조한다.
- 테스트 폼의 응답 확인은 편집 URL·계정·연락처가 영상에 보이지 않도록 따로 준비한다. 응답 원본·관리 화면 캡처는 저장소에 넣지 않는다.
- LLM이 미연결이면 대화 장면은 UI 시연으로 구분한다. 구글폼 실제 제출과 LLM 실제 응답 검증은 별개다.

## 7. 실제 대화 초안

### A. 필요한 정보만 받기

**사용자:** “천호동 근처에서 가볍게 사람 만날 활동이 있을까? 큰 모임은 조금 부담돼.”

**조이:** “서울 강동구 천호동이 맞나요?”

선택지: `[맞아요]` `[다른 지역이에요]`

**조이:** “대상 나이를 확인하려고 해요. 생년월일을 알려주세요. 건너뛰어도 괜찮아요.”

**사용자:** “2003년 6월 20일.”

**조이:** “지금 어떤 상태인가요?”

선택지: `[재학 중]` 등 실제 지원 항목. 재학 중을 선택하면 학교 구분을 이어서 묻는다.

**사용자:** “대학생.”

관심은 `[사람 만나기·모임]` `[문화·여가]`로 정리하고, 대면 부담은 사용자가 직접 답한 경우에만 반영한다. 단순히 활동을 찾는다는 이유로 생활 부담을 추정하지 않는다.

### B. 폼 문항을 한 번에 읽고, 저장된 정보로 일괄 초안 작성

**사용자:** “이 프로그램 신청 도와줘.”

**조이:** “신청서에서 필요한 항목을 먼저 확인할게요. 이미 알려준 정보는 한 번에 채우고, 확인이 필요한 것만 물어볼게요.”

실제 공고를 살펴본 뒤 제출 장면은 팀 소유 테스트 폼으로 전환한다. 화면에 **‘팀 소유 테스트 신청서’** 표시를 유지한다.

화면: 문항 전체를 읽은 후 한 장의 신청서 초안을 보여준다.

| 분류 | 예시 | 처리 |
|---|---|---|
| 이미 알고 있는 정보 | 가상 이름·생년월일·강동구 거주 | 폼이 요구하는 항목에만 일괄 반영 |
| 형식 확인 | 생년월일 형식·필수 선택 누락 | 폼 조건에 맞춰 검증하고 오류 위치 표시 |
| 모르는 사실 | 참여 가능한 회차·필수 연락 정보 | 해당 항목만 추가 질문. 추측하지 않음 |
| 긴 서술 | 참여 동기 | 알려준 사실을 바탕으로 추천 답변 제시·수정 가능 |
| 동의 | 개인정보 처리·참여 동의 | 사용자가 직접 선택 |

여기서 ‘한 번에 입력’은 모든 문항을 확인한 뒤 **알고 있는 값으로 전체 초안을 채우는 것**이다. 매 문항마다 사용자에게 입력을 시키거나, 부족한 필수값을 임의로 채우는 흐름으로 만들지 않는다.

**조이:** “알려준 정보는 채웠어요. 참여 회차와 참여 이유만 확인하면 돼요.”

추가 질문 카드: `[토요일 오후]` `[다른 회차]` 등 **실제 테스트 폼에 있는 선택지만** 표시한다.

**사용자:** “토요일 오후. 동네에서 편하게 사람 만나고 싶어서.”

**조이:** “참여 이유는 이렇게 쓰면 어떨까요?”

추천 답변: “동네에서 새로운 사람들과 편하게 교류하고 지역 활동을 시작해 보고 싶어 참여를 희망합니다.”

버튼: `[이 답변 사용]` `[직접 수정]`

사용자가 채택한 답변을 전체 초안에 반영한다. 남은 필수 문항·형식 오류만 다시 확인한다. 알려준 정보는 재질문하지 않는다. 폼에 없는 문항이나 선택지를 영상용으로 끼워 넣지 않는다.

### C. 최종 확인 → 승인 → 실제 테스트 접수 완료

**조이:** “이 내용으로 신청할까요?”

최종 확인 카드:

- 대상: 팀 소유 테스트 신청서
- 문항별 제출 답변 전체와 사용자가 선택한 동의
- 수정한 추천 답변
- `[수정하기]` `[이 내용으로 신청]` `[취소]`

**사용자:** “응, 신청해 줘.” 또는 `[이 내용으로 신청]`

화면: 제출 중 중복 클릭 방지 → 성공 확인 후 완료 카드.

**조이:** “테스트 신청서가 접수됐어요. 신청 기록을 남겼어요.”

마지막 문장은 실제 기록 저장까지 성공한 경우에만 사용한다. 제출 결과가 불명확하면 완료라고 하지 않고 접수 여부를 먼저 확인한다.

촬영 성공 근거는 기존 성공 경로에서 서버 접수 결과와 팀 소유 폼의 응답 추가를 대조한다. API가 접수번호를 주지 않으면 만들지 않는다. 테스트 폼에 ‘센터에서 연락이 올 거예요’라는 실제 기관 연락 약속을 붙이지 않는다.

#### 신청 완료 카드의 날짜 표시

| 정보 | 표시 규칙 |
|---|---|
| 신청 기간 | 원문에 있을 때만 시작~마감 표시 |
| 참여 일정·지원 기간 | 실제로 확인된 경우 별도 라벨로 표시 |
| 기간이 없는 폼 | ‘신청일: 실제 접수 일시’ 표시. 기간을 만들지 않음 |
| 신청일 | 서버 접수 시각을 한국 시간으로 표시. 제출 전 고정값으로 만들지 않음 |
| 결과 상태 | ‘접수 완료’. 선정·참여 확정과 구분 |

신청 기간은 접수 가능한 기간이며 행사일과 다르다. 문의 일정은 접수 기록만으로 임의 생성하지 않고 다음 장면에서 확인받는다.

### D. 전화 대신 문의 대본과 일정

**사용자:** “처음 가는데 준비물이 있는지 모르겠어. 대신 전화해 줄 수 있어?”

**조이:** “전화 대행은 아직 지원하지 않아요. 준비물을 확인할 때 사용할 대본을 정리해 드릴게요.”

문의 대본 카드:

> 프로그램 참여를 준비하고 있어요. 처음 참여하는 사람도 가능한지, 별도로 준비할 물품이나 서류가 있는지 확인하고 싶어요.

선택지: `[대본 복사]` `[문의할 일정 등록]` `[공식 안내 보기]`

**사용자:** “11월 24일 오전 11시에 문의할 일정 넣어 줘.”

조이는 종료 시간을 임의로 늘리지 않는다. 촬영에서는 사용자가 11:00~11:15로 확인한다.

문의 일정 카드:

| 필드 | 값 |
|---|---|
| 제목 | 강동 프로그램 준비물·참여 조건 문의 |
| 날짜·시간 | 2026-11-24(화) 11:00~11:15 |
| 성격 | 문의할 일 · 아직 문의하지 않음 |
| 메모 | 첫 참여 가능 여부, 준비물·서류 확인 |
| 장소 | 온라인 공식 안내 확인 후 사용자가 직접 문의 |

버튼: `[확인하고 등록]` `[내용 수정]` `[취소]`

이 일정은 전화 예약·자동 발신이 아니다. 정한 시간이 됐다고 조이가 전화를 수행하지 않는다.

### E. 테스트 참여 일정과 마무리

**조이:** “테스트 신청서의 참여 일정도 남길까요?”

화면: **`[시연용] 강동 청년 교류 모임`**, 2026-12-05(토) 14:00~16:00, 실제 예약이 아닌 가상 장소 표시.

사용자 확인 후 내 일정 리스트에서 다음을 함께 보여준다.

1. 11월 24일: 준비물·참여 조건 문의할 일
2. 12월 5일: 시연용 모임 참여 일정

신청 기록에는 팀 테스트 폼 접수임을 표시한다. 저장한 일정과 신청 이력이 새로고침 후에도 유지되는지 확인한다.

## 8. 필수 영상의 완료 범위와 선택 확장

| 필수: 페르소나 1 | 선택: 페르소나 2 |
|---|---|
| 강동구 수아, 교류·문화 관심 | 관악구 지민, 주거·생활 부담 |
| 대화로 필요한 정보 수집 | 설문으로 정책 추천 |
| 검증한 팀 구글폼 문항 일괄 읽기·초안 작성 | 외부 정책 신청 화면과 조이를 반반 표시 |
| 부족한 정보만 질문·추천 답변 수정 | 로그인 완료 후 현재 화면의 다음 행동 안내 |
| 최종 승인 후 테스트 접수 | 소득 증명 등 필요 서류 발급 방법 안내 |
| 문의 대본·문의 일정·접수일 기록 | 가능하면 신청 확인, 어려우면 준비 일정으로 종료 |

**2번을 촬영하지 않아도 1번만으로 영상이 완결돼야 한다.** 반반 화면·정책 사이트 연동을 구글폼 영상의 선행 조건으로 두지 않는다.

## 9. 현재 상태와 촬영 전 확인

- 사용자 공유 상태: **구글폼 테스트 완료, 시연 가능**. 이번 문서 작업에서는 재제출하지 않았다.
- 구글폼 전체 문항 읽기 → 일괄 초안 → 누락만 질문 → 추천 답변 → 승인 → 완료가 실제 연결된 범위인지 촬영 리허설에서 확인한다.
- 기존 테스트 성공과 전체 챗봇·프론트 연결 완료를 같은 의미로 쓰지 않는다. 없는 UI 장면은 연결 후 촬영하거나 실제 동작 범위로 대본을 줄인다.
- 문의 대본과 문의 일정은 실제 전화 없이 끝낸다. 문의 완료라고 기록하지 않는다.
- 일정은 실제 저장된 항목을 리스트·달력에서 보여준다. 참여일이 없는 신청서는 문의 일정과 접수일만 남긴다.
- 자연스러운 자유 대화와 반반 외부 화면 연동은 이 문서에서 새로 구현·검증한 기능이 아니다.

## 10. 오류·촬영 중단 기준

- 폼 마감: ‘접수 마감’을 안내하고 제출하지 않는다.
- 필수 문항 누락: 해당 문항만 다시 묻는다. 저장된 다른 정보는 다시 묻지 않는다.
- 동의 미선택: 제출하지 않는다.
- 제출 실패·시간 초과: 성공 처리하지 않는다. 실제 접수 여부를 확인하기 전 자동 재시도하지 않는다.
- 팀 소유 폼인지 불명확: 제출하지 않고 시연 중단.
- 실제 공고와 가상 일정이 섞임: 카드의 표시와 대본을 고친 뒤 촬영.
- 개인 계정·폼 주소·연락처 노출: 장면을 다시 찍거나 가린다. 응답·관리 화면 원본을 저장소에 넣지 않는다.

## 11. 영상용 한 문장

> “조이가 필요한 정보만 받아 테스트 신청서 제출까지 돕고, 직접 확인해야 할 문의는 대본과 일정으로 이어줍니다.”
