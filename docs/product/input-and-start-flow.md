# 사용자 입력과 첫 시작 흐름

2026-11-20 구현 기준. 프론트 기존 화면과 로컬 데이터를 유지한다. 실제 회원가입/계정/챗봇 API는 추가하지 않았다.

## 화면과 입력 확정표

| 화면 | 항목 | 저장·전달 | 결정 |
|---|---|---|---|
| 내 정보 | 생년월일·거주 지역 | 로컬 원문 → 만 나이/시군구5자리만 추천 전달 | 첫 시작 선택 입력. 기존 전국 지역 선택을 유지하고 서울 중심 안내. 청년 연령을 임의 확정/차단하지 않음 |
| 내 정보 | 이름·전화·이메일 | 로컬만 | 마이페이지에서 선택 입력. 첫 시작에서는 제외 |
| 맞춤 설정 | 현재 상태·재학 상태 | job/school 변환 후 서버 전달 | 유지. 선택 안 함 허용 |
| 맞춤 설정 | 관심 분야 최대3개 | checkin.interests | 유지. 최신 저장 출처를 다음 추천에 사용 |
| 맞춤 설정 | 참여 방식·모임 규모 | 로컬만 | 유지하되 현재 추천 미반영 안내. backend 계약 전에는 임의로 대면 부담 답변으로 변환하지 않음 |
| 생활 점검 | 서버의9문항 | 응답코드로 서버 요약/추천 | 유지. 전체 생략/문항별 생략/거절 허용 |
| 내 기록 | 활동 경험 추가·수정·삭제 | 기존 activity.experiences 로컬 키 그대로 | 맞춤 설정에서 이동. 삭제/초기화/재수집하지 않음 |
| 정책/프로그램별 대화 | 소득·가구·세부 자격·신청용 추가 정보 | 미구현 | 처음부터 수집하지 않음. 실제 필요한 시점에만 묻도록 후속 챗봇 계약 정의 |

## 첫 시작 (피드백 반영)

`홈의 처음 시작하기 → 내 정보 → 맞춤 설정 → 생활 점검 → 결과·추천`.

- 첫 방문에도 홈을 먼저 보여준다. 생활 점검 완료 이력이 없는 사람에게만 ‘처음 시작하기’를 표시한다. 완료한 사람은 마이페이지에서 수정·다시 점검한다.
- 별도 소개 화면, 상단 단계 탭, 반복 안내 패널, 상단 ‘이 단계 건너뛰기’는 없다.
- 시작 버튼을 누르면 첫 입력 또는 중단한 입력으로 바로 들어간다. 내 정보·맞춤 설정 하단의 ‘다음’으로 저장하고 자동으로 다음 화면으로 이동한다.
- 이름/연락처는 첫 설정에서 수집하지 않는다. 건너뛰기는 폼 맨 아래의 작은 ‘나중에 하기’로 제공한다. 생활 점검도 하단에서 나중에 할 수 있다.
- 완료하지 않고 나왔으면 홈의 시작 버튼이 유지된다. 저장값/진행 위치는 유지하지만 새로고침 시 강제로 설정 화면을 띄우지는 않는다.
- 저장하지 않은 폼 초안은 보존을 보장하지 않는다. 부분 입력/미입력도 다음으로 진행할 수 있다.

## 다시 점검과 이력

- 마이페이지 ‘생활 점검 다시 하기’와 생활 점검 메뉴는 설문부터 연다. 이전 결과나 이력 목록을 먼저 펼치지 않는다.
- 최근 관심이 맞춤 설정에서 왔다면 관심만 재사용하고 나머지 문항은 새 응답을 받는다.
- 설문 위 ‘이력 보기’를 누르면 과거 목록으로 이동한다. ‘점검으로 돌아가기’로 작성 중 설문으로 복귀 가능하다.
- 과거 결과를 선택해 열 수 있고, 결과에서 다시 점검하면 설문으로 돌아간다. 작성 이력은 지우지 않는다.
- 입력 생략/거절 로컬 메타데이터와 서버 추천 계약은 이전 구현을 유지한다.

## 공통 저장과 관심 우선순위

기존 personal/activity/checkin-history 키를 변경하지 않는다. `dos-tres.setup.v1`만 추가해 단계, 완료 여부, 항목 결정, 최신 관심 출처를 보관한다.

- 신규 메타데이터 없는 기존 사용자는 기존 진단 관심 우선 규칙으로 시작한다.
- 맞춤 설정에서 관심을 변경해 저장하면 그 값이 다음 추천에서 우선한다. 온라인 선호 등 다른 항목만 저장하면 관심 출처를 바꾸지 않는다.
- 생활 점검 결과를 새로 저장하면서 관심에 답하면 그 답변이 최신 출처가 된다. 가장 최근 출처가 프로필이면 점검 진입 시 관심을 재사용해 중복 입력을 줄인다.
- 관심을 명시적으로 비운 변경도 적용한다. 과거 이력의 응답/서버 요약은 수정하지 않는다. 과거 이력을 명시적으로 조회하는 화면은 당시 답변을 사용한다.

## 미응답·건너뛰기·거절

미결정은 키 없음, 선택 응답은 answered, 이번 생략은 skipped, 답하지 않겠다는 선택은 declined로 구분한다. 해당 문항에 답하면 answered로 갱신한다. 문항 생략/거절 시 현재 선택을 해제하고, 다음 추천에서 과거 이력의 해당 답을 되살리지 않는다. 과거 이력은 그대로 보존한다.

메타데이터는 backend 질문 코드로 전송하지 않는다. 현재 chatbot은 연결되지 않았다. 후속 챗봇 구현은 이 정보를 읽어 다음 규칙을 적용해야 한다.

- 저장된 유효한 값은 재사용하고 필요한 경우 변경 여부만 확인.
- skipped는 현재 목적에 필요할 때 입력 여부를 제안하되 강제로 묻지 않음.
- declined는 자동으로 재질문하지 않음. 사용자가 직접 설정을 바꾸거나 답할 의사를 표시한 경우에만 수집.
- 추천 요청에는 필요한 조건과 답변만, 신청용 연락처는 별도 확인된 목적에서만 사용. 로컬 전체 객체를 통째로 LLM에 보내지 않음.

## 백엔드 협의 항목 (미전송)

1. 챗봇 context/응답 계약: 필요한 입력, missing_fields, 선택지, 생략/거절 처리, 저장값 갱신 제안.
2. participation_preference/group_size와 프로그램 운영방식/규모 메타데이터. 현재 미지원이므로 UI에서 사용한다고 주장하지 않음.
3. 선택 지원별 추가 자격 질문을 어떤 필드로 제공할지. 프론트가 독자적으로 정책 자격을 추정하지 않음.

## 검증

- Chrome 127.0.0.1 기존 저장소: 기본 정보·관심1건·신청1건·점검6건 유지, 단계별 생략→생활 점검→정책 화면, 문항 거절 상태 표시, 마이페이지 명칭/내 기록의 경험 편집 이동 확인.
- Chrome localhost 별도 origin: 기존127 저장소를 지우지 않고 신규 첫 시작 노출, 연락처 미수집, 내 정보 생략→새로고침→맞춤 설정 단계 복원, 주거 관심 저장→점검에서1응답으로 재사용, 종료→새로고침 시 홈 복귀 확인. 테스트 관심은 localhost 저장소에만 남아 있음.
- 저장 차단/손상·진행 위치·생략/거절 구분: verify-setup-state.mjs.
- 최신 관심·명시적 빈 관심·거절한 과거 답변 배제·추천 요청 필드와 backend11계약: verify-profile-context.mjs.
- 기존 이력 검사, 문항/요약 검사, 로컬 저장 검사, TypeScript/Vite 빌드, diff 검사.
- 실제 챗봇 질문·로그인/가입·실제 신청·배포는 검증 대상 아님. 모바일 전체·키보드 전수 검증은 미완료.

### 시작·재점검 동선 피드백 검증

Chrome의 완료 이력6건이 있는127저장소에서 홈 시작 CTA 미노출, 마이페이지 재점검→설문 먼저/이력 숨김→이력 보기6건 확인. localhost 미완료 저장소에서 시작 CTA 노출→생활 점검 중단 위치로 직접 진입, 상단 단계/건너뛰기 메뉴 없음과 하단 작은 생략 버튼 확인. 기존 값을 삭제하거나 새 점검 결과를 저장하지 않았다.
