## 후속 1단계 · 실제 DB 연결 기준 확정 (2026-11-20)

이 절은 위의 과거 file/DB 미검증 판정을 현재 연결 상태에 한해 갱신한다. 전체 기능을 다시 통과시킨다는 뜻은 아니다.

- 시작 시 기존 frontend 미커밋 변경을 그대로 보존. backend main 변경 없음.
- 이번 시작 시 Docker가 꺼져 있고 기존 backend-db-1도 중지돼 있었다. Docker를 실행하고 **기존 DB 컨테이너만 재시작**했다. DB 재생성·migration·재적재·비밀번호 변경 없음. 프론트5173과 backend8000 실행 유지.
- PostgreSQL 직접 읽기: policy 2,335 / program 169, Alembic 0004, container healthy.
- 브라우저 GET `/readyz`: `{"status":"ok"}`. 별도 실제 TCP GET에서도 HTTP200 확인.
- 합성 조건 age=24, sigungu_cd=11620, checkin={}로 POST `/api/recommendations`: **HTTP200, source=db**, 정책6/프로그램4, 후보 정책119/프로그램133.
- 동일 조건으로 Vite5173 `/api/recommendations` 실제 HTTP 요청: HTTP200, source=db. backend8000 직접 응답과 **전체 JSON 동일**.
- Chrome 기존 FE 화면에서 정책 메뉴 진입 후 ‘조건별 추천 10건’, ‘DB에 저장된 수집 데이터 기준 추천이에요.’ 문구 확인. 사용자 기본 정보는 변경하지 않음.
- CLI 로컬 curl은 접근 제한이 있어 Docker의 기존 DB 컨테이너에서 host.docker.internal로 실제 HTTP 요청. ASGI 대체가 아니다. 응답의 개인 연락처/폼 링크를 출력하지 않고 출처·건수·표본 제목만 추출.
- 근거 요약: `step1-db-connection-2026-11-20.json`.

**현재 1단계 판정: 실제 API + DB 정상, 프론트 프록시 정상, DB 출처 화면 반영 정상. 이 단계에서 백엔드 코드 수정 요청은 없음.** 과거 ‘DB 오류 후 file 대체’는 당시의 상태로 보존하되 현재 장애로 해석하지 않는다.

### 이후 검증의 기준 (사용자 방향)

회원정보는 브라우저 로컬 보관. 이름·전화·이메일·생년월일 원문을 추천 API에 보내지 않고 필요한 만 나이·시군구·현재 상태·재학 조건 및 선택 답변만 전달한다. 자가진단 계산·추천 순서/이유·기간·소득 조건·안내는 백엔드 응답을 기준으로 표시한다. 프론트는 표시 형태 변환과 사용자 조작을 담당한다. 저장한 점검 이력은 당시 응답의 로컬 보관본이며 새로운 서버 계산처럼 표현하지 않는다.

현재도 전체 탐색·상세 보충은 로컬 수집 스냅샷, 지역 선택은 프론트 사전, 센터는 예시 데이터인 경로가 있다. 백엔드 최대 활용 방향에 맞춰 다음 단계에서 필요한 목록/상세 필드와 API를 구체화한다. 연결 검증만을 위해 이 경로들을 이번에 임의로 변경하지 않았다.
