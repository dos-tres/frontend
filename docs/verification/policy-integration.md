# 정책·프로그램 연동

## 구현

- 백엔드 seed 정책 2,335건/센터 프로그램 169건을 공개 표시 필드로 변환한 스냅샷으로 목록·상세 표시.
- 제목/요약/분류/운영기관 검색, 정책·프로그램 필터, 마감 제외, 관심 저장/해제 및 관심 목록, 정렬, 12개씩 페이지 이동.
- 상세 지원 대상·신청 기간·지원 내용·소득 조건·신청 방법·서류·참여 제한·출처 링크. 비어 있는 선택 항목과 `-`는 숨김.
- 공식 공고/신청 URL은 HTTP(S)만 허용. 누락된 링크는 임의 생성하지 않음. 마감 여부는 로컬 날짜 기준으로 판단하고 마감 당일까지 포함.
- 상세에 선택한 객체를 그대로 전달하므로 API에서 새로 들어온 id도 상세·신청 준비·관심 저장에 사용 가능.
- 내 정보의 만 나이+시군구 적용 시 `POST /api/recommendations` 호출. 현재 활동 상태를 백엔드 job 값에 맞춰 전달하며, 보관한 자가진단 답변도 함께 전달.
- API 응답의 정책 최대 6개·프로그램 최대 4개와 추천 이유·센터 데이터 없음 안내 표시. 이때 검색은 추천 결과 안에서 적용.
- API 실패/3초 시간 초과 시 입력 조건을 유지하고 스냅샷 목록 탐색 유지. 별도 예시 배너 없음. 로컬 목록은 연령/지역/마감 필터이며 백엔드 자격 규칙·추천 점수와 같지 않음.
- 소득 조건은 표시만 함. 자동으로 신청 자격을 확정하지 않으며 신청은 공식 사이트에서 진행.
- 기존 전역 스타일 재사용, 모바일 1열 폼/목록. 정보/관심 목록은 기존과 같이 React 메모리에서만 유지.

## 데이터·지역 코드

`scripts/export-policy-snapshot.py`를 frontend에서 실행하면 형제 `backend/data/seed/serving`에서 재생성.
지역 선택지는 행정표준코드관리시스템에서 2026-11-20 직접 내려받은 전체 법정동코드 원본 중 현존 자료로 구성합니다. 정책 기관명에서 지역명을 추론하던 방식은 폐기했습니다.

- 현존 시·도 16개, 시군구/시 전체 코드 269개, 읍면동 5,067개.
- 부산 16개 구·군과 대구 9개 구·군 전체 이름/코드를 원본과 대조.
- 마이페이지도 같은 공식 코드/이름을 사용. 통계코드와 법정동코드를 혼용하지 않음.
- 시 전체와 하위 일반구를 모두 보존. 시 전체를 고르면 하위 구 코드의 정책도 포함.
- 정책 데이터가 없는 지역도 선택 가능. 추천 API가 아직 지원하지 않는 시 전체/지역은 로컬 목록 탐색을 유지.
- 원본 ZIP 및 해시 보관. 재생성 `python3 scripts/import-administrative-regions.py`, 전체 대조 `python3 scripts/verify-administrative-regions.py`.
- 출처/재생성 규칙: [지역 코드 원본](../../src/data/regions-source.md).

목록·상세용 일반 조회 API가 백엔드에 없으므로 공개 스냅샷을 지연 로딩. 전체 데이터 청크는 압축 전 약 3.8MB이며 빌드 크기 경고가 남음. 홈 최초 로딩에서는 이 청크를 불러오지 않음.
수집 시점은 2026-11-19이며 외부 공고의 현재 유효성·링크 접근성까지 보장하지 않음.

## 백엔드 추가가 필요한 API 예시 (구현하지 않음)

사용자 요청에 따라 필요한 변경은 예시로 기록하고 기존 백엔드 코드는 보존.

```text
GET /api/catalog?query=주거&kind=policy&sigungu_cd=11620&age=24&open_only=true&page=1&page_size=12
→ {items: [...], total: 120, page: 1, page_size: 12, updated_at: ...}

GET /api/catalog/{id}
→ 지원 대상/내용/서류/신청 방법/운영기관/원문 URL을 포함한 상세

GET /api/regions
→ 백엔드 데이터와 같은 코드 체계의 [{code, label}, ...]
```

이 API가 추가되면 브라우저 전체 스냅샷 대신 서버 검색·페이지네이션으로 전환 가능.
추천 API는 요약/support를 200/300자로 줄여 반환하므로 전체 상세 원문을 제공하는 별도 endpoint가 필요.

## 지역 선택/기본 조건 개선

- 시·도와 시·군·구를 분리하고 선택 즉시 필터 적용. 시·도 변경 시 기존 시군구 초기화. 시·도 전체는 2자리 prefix로 로컬 조회하며 추천 API에 잘못된 2자리 지역을 보내지 않음.
- 나이 입력 중복 제거. 저장된 생년월일로 만 나이 계산, 프로필의 활동 상태도 자동 전달. 생일 당일/전날, 잘못된 날짜/미래 날짜, 빈 날짜 검증.
- 저장한 지역 이름으로 일치하는 시군구 우선 적용; 없으면 시·도 fallback. 기존 프로필의 광주광역시·전라남도 명칭은 백엔드의 전남광주통합특별시 명칭에 맞춤.
- 프로필 변경 시 기본 조건 갱신, 사용자가 선택한 타 지역은 이동 중 유지, `내 지역으로` 초기화 시 프로필 조건 복원.
- Chrome에서 시·도 목록 표시, 서울 → 관악구 선택 및 목록 변경, 충북 선택 시 전체 시군구로 초기화되는 것 확인. 프로필 자동 조건은 함수 검증으로 확인.

## 지역 누락 수정 검증

- 공식 원본 53,403행 중 현존 20,560행에서 지역 사전을 재생성. 생성된 시·도/시군구/읍면동의 모든 코드·이름이 원본과 동일함을 검증.
- 정책 카탈로그의 region 목록도 공식 사전 전체와 같음을 검증하여 정책 보유 지역만 남기는 회귀 방지.
- 부산 16개 구·군, 대구 9개 구·군의 완전한 이름 목록 별도 검증. 수원시 전체 선택에 영통구 코드가 포함되는지 검증.
- Chrome 실제 UI에서 부산 전체 16개 구·군 선택지 표시 확인. 이후 사용자의 브라우저 조작 감지로 추가 UI 조작을 중단했으며 대구는 원본 대조 테스트로 검증.
