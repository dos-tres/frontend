# 조이 대화 구현과 검증

- 기준: 최신 origin/main f643523, feat/joy-conversation. 별도 worktree로 기존 홈 디자인의 미커밋 변경 보존.
- 홈 질문 → 대화, 정책·프로그램 상세 → 해당 Program(id 포함)을 전달한 새 대화.
- 항목 진입마다 대화 키를 바꿔 이전 항목·작업 상태를 초기화. 일반 메뉴 이동 시 대화는 유지.
- 새 대화: 메시지·항목·작업 초기화, 이번 탭의 사용자 입력 정보 유지. 새로고침 시 전체 초기화.
- 기본 가상 사용자 정보는 서울 강서구 염창동뿐. 나이·활동 상태는 선택적으로 카드에서 입력·수정.
- 조건 결과는 현재 정보로 즉시 재계산. 공식 공고 미연결 조건은 계속 ‘추가 확인 필요’.
- 작업은 준비 중 → 사용자 확인 필요 → 진행 중 → 시연 완료/실패. 요청 내용과 사용할 정보를 검토·수정 가능.
- 완료 결과의 사용 정보는 실행 당시 스냅샷으로 보존. 새 정보는 다음 작업에 사용.
- 완료 후 준비 이력을 기존 Application[]에 ‘신청 전 / 시연용 예시’로 저장. 실제 접수 성공으로 저장하지 않음.

## 연동 경계

기존 프로젝트에는 라우터 라이브러리, API 클라이언트, 프로필 API, 영속 저장소가 없다. 기존 screen 상태 전환과 App 메모리 저장 구조를 유지한다. 실제 API 연결 범위는 없음. `src/joy-demo.ts`의 응답/실행 어댑터와 조건 함수는 전부 명시적 시연이다. 서울 거주·만 19~34세·미취업은 가상 조건이며 실제 공고에서 가져온 조건이 아니다. Program.source에 실제 http(s) URL이 공급될 때만 원문 링크를 표시한다.

## 리뷰 시 직접 확인할 흐름

1. 홈 질문 또는 상단 ‘조이에게 묻기’ → 대화 진입.
2. 정책 목록 → 상세 → ‘조이야, 나도 신청할 수 있어?’ → 항목 이름과 조건 확인.
3. 만 나이 25, 미취업 입력 → 조건 갱신. 35세 또는 재직으로 수정 → 미충족. 정보 근거 펼치기.
4. 신청·문의·예약 선택 → 작업 내용 확인 → 요청 내용·사용 정보 수정 → 시연 진행 → 결과 확인.
5. ‘시연 상태 확인 도구’에서 실패 재현 체크 → 메시지/작업 실패 → 체크 해제 → 재시도.
6. 준비 이력 저장 → 이력 보기 → 상단 조이에게 묻기로 돌아가 대화 유지 확인.
7. 다른 정책 상세에서 진입 → 이전 항목·작업 제거 확인. 새 대화 → 입력한 내 정보 유지 확인.
8. PC 우측 작업 요약, 모바일 대화 안 작업 요약; 긴 메시지·카드와 입력창 sticky 배치 확인. 모바일 실제 키보드는 실기기 확인 필요.
