# 센터·일정과 조이 연결

기준: frontend main 13df52d에서 feat/assistant-schedule 분기. 백엔드는 변경하지 않음.

## 구현

- 센터 상세의 ‘조이에게 센터 물어보기 · 방문 일정 잡기’가 센터 공식 안내·주소 맥락을 대화로 전달.
- 조이에서 센터 소개·시설·이용 안내 확인, 센터 방문 일정은 주소·센터 ID 함께 저장.
- 직접 입력과 대화 입력은 App의 단일 events 저장 경로 사용. 기존 날짜·제목만 있는 로컬 기록도 유지.
- 내 일정은 날짜별 시간 축 블록, 겹치는 일정은 별도 열, 시간 미정 일정은 별도 목록 제공. 직접 등록·수정·삭제 확인 지원.
- 대화는 오늘/내일/모레/요일/ISO 날짜, 오전·오후 시각, 시간 미정 입력 지원. 부족 정보 질문, 저장 전 확인. 일정 이름으로 수정·삭제 요청 지원. 날짜/종료 시각 검증.
- 시작 시각 기준 선택한 분 전 알림. 페이지가 열려 있을 때 15초 주기로 확인. 재방문·새로고침 시 중복 발송하지 않도록 notifiedAt 저장. 알림 권한은 ‘브라우저 알림 켜기’를 누를 때만 요청. 거부해도 화면 알림 유지.
- 공고 대화에서 ‘직접 신청한 내역 기록’은 사용자 진술로 신청 완료 이력 기록 후 참여 날짜를 따로 질문. 실제 기관의 접수 확인으로 표시하지 않으며 마감일을 참여 날짜로 추정하지 않음.

## 검증

- verify-schedule.mjs: 날짜/시간 해석, 모호한 시간 보류, 잘못된 날짜/종료 시각, 알림 시점/중복/지난 일정, 겹치는 블록 배치.
- verify-schedule-display.mjs: 실제 React 정적 렌더로 시간 축 위치·높이, 편집 필드, 센터→비서 버튼, 일정 컨트롤, 알림 제한 문구 확인.
- 기존 local-storage/profile-chat/center-display 회귀 스크립트 통과.
- TypeScript + Vite build 통과(기존 청크 크기 경고 유지).

## 미검증·후속

- 브라우저 조작 도구가 없어 실제 클릭·대화·기기 Notification 표시·모바일 시각 결과는 미검증. React 렌더 검사를 브라우저 검증으로 간주하지 않음.
- 자유 LLM 대화 및 /api/apply/submit 프론트 연결은 기존에도 없었고 이번 변경에 포함되지 않음. 현재 일정 명령은 제한된 날짜/시간 해석이며 모르는 표현은 저장하지 않고 확인이 필요함.
- AI 신청 성공 응답을 받는 UI가 아직 없으므로 ‘AI가 제출한 신청 자동 기록’은 미구현. 해당 경로에서 실제 응답의 status=submitted를 확인한 뒤 신청 이력과 같은 일정 저장 경로를 호출해야 함. HTTP 200이나 신청 시작만으로 완료 처리하면 안 됨.
- 창을 닫은 뒤의 푸시/문자/이메일 알림은 미구현. 서버 알림 작업자·구독 API가 없으며 현재 브라우저 로컬 저장만 사용.
- 실제 기관 신청·문의, 외부 폼 제출은 수행하지 않음. 비밀값·개인 연락처·폼 링크 추가 없음.
