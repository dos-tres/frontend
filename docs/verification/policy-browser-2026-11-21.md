## 출처와 남은 작업

source=db와 source=file을 API에서 구분하며 file은 백엔드 원본 파일 대체 결과다. 프론트 자체 정적 카탈로그를 실패 대체로 사용하지 않는다. 목록 조회는 현재 카탈로그 전체를 읽어 필터하므로 규모 확대 시 DB 조건/페이지 처리로 옮길 필요가 있다.

실제 AI 단계는 선택 공고 ID와 로컬 정보의 허용 필드를 받는 대화 API, 근거 기반 응답/부족 정보 질문 계약이 필요하다. 자동 신청·전화는 이번 작업에 포함하지 않는다. 프론트와 백엔드 두 변경을 함께 검토해야 한다.

화면: http://127.0.0.1:5173/ → 정책·활동 찾기 → 분야 선택 → 조이와 알아보기 → 내 조건 확인/신청 방법. 서버 유지.

## 2026-11-21 · 웹 AI 비서 대화 동선 수정

- 사용자 피드백에 따라 별도 공고 상세/탭 방식 안내를 제거하고 AI 비서 공통 대화 화면으로 통합했다. 정책 선택 시 사용자 요청과 조이의 공고 소개가 대화에 표시된다.
- 선택지는 대화에 질문·답변으로 누적되고 직접 입력도 지원한다. 내 조건/지원 내용/신청 방법은 서버 공고와 로컬 저장 정보로 안내한다. 자유 LLM 대화·자동 신청은 아직 미연결이며 명시한다.
- 피클의 설명→선택지→후속 안내 방식을 참고하되 데스크톱 웹은 좌측 공고 맥락/우측 대화의 넓은 레이아웃을 사용한다. 참고 이미지의 연락처·개인정보는 복사/코드화하지 않았다.
- 기존 가짜 최근 대화 목록과 고정 예시 답변을 화면에서 제거했다. 새 대화는 현재 화면 대화만 초기화한다. 대화 영구 저장은 아직 구현하지 않았다.
- npm run build 및 verify-policy-browser 통과. 실제 브라우저 정책 선택→AI 비서, 선택지 응답 누적, 직접 입력 응답 확인. 1440×1000 데스크톱과 390×844 모바일 확인, 임시 뷰포트 복원. JS 청크 크기 경고는 유지.
- 커밋·푸시·PR 변경·배포 없음. 로컬 서버 유지.

## 2026-11-21 · 대화창에서 내 정보 한 항목씩 입력

- ‘내 정보 입력’/좌측 수정 동작/직접 입력 요청이 별도 설정 페이지 대신 대화 안에서 생년월일→지역→현재 상태→재학 상태→관심 분야를 한 항목씩 묻는다.
- 유효한 답은 기존 App의 savePersonal/saveActivity 경로로 즉시 반영해 로컬 저장·마이페이지·후속 추천 입력을 공유한다. 이름·연락처는 묻지 않는다. 기존 필드와 활동 경험은 보존한다.
- 이미 저장된 항목은 기존 값 유지/수정 선택, 건너뛰기/중간 종료 지원. 관심은 최대 3개 선택 후 완료 시 저장. 날짜·지역·허용 선택 검증 실패 시 해당 질문 유지.
- 빌드 통과. verify-profile-chat(날짜/미래일/윤년/지역 중복/선택지/관심 제한), verify-local-storage, verify-profile-context 통과.
- 실제 브라우저에서 설정 페이지 이동 없이 순차 질문, 잘못된 날짜 재안내, 건너뛰기, 관심 3개 제한, 종료 후 재진입 확인. 테스트 입력은 저장 완료하지 않아 사용자 프로필에 합성 데이터를 추가하지 않았다. 실제 사용자 답 저장 후 재방문까지의 브라우저 검증은 별도로 남는다(로컬 저장 회귀 검사는 통과).
- 커밋·푸시·PR 갱신 없음. 서버 유지.
